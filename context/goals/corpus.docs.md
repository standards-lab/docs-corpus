## Task brief · corpus.docs · curate

**Problem**

The review recorded which `~/docs` samples stay and named a candidate for every gap, but
docs-corpus still holds no corpus. Snapshot can't tag v1, and baseline can't run, until the
curated set exists. That means each sample in place with its truth, provenance, and covers in the
review's vocabulary, an inventory recording them, a fetch that verifies the payload, and a check
that refuses duplicate scenarios. The coverage tooling also still copies Python's JSON output for
scripts that have been deleted.

**Behaviors**

1. tools/coverage writes all JSON with Go's standard encoder from typed structures. The output
   uses two-space indent, no HTML escaping, and a trailing newline, with key order set by field
   order and ID-keyed objects sorted by key. The Python-emulating JSON package is gone. The
   coverage data is reformatted once, in its own commit, with no content change, shown by
   sorted-key equality with the old file. After that, place-traits and dispose reproduce it byte
   for byte.
2. The repository carries the workspace's Apache-2.0 license. The generated candidates whose
   generator is the repository's own code name Apache-2.0 as their generator license.
3. The manifest has `version: 1` and one entry per corpus file. The role is sample, truth, or doc.
   Each entry records:
   - path, sha256, bytes, and format (format is what `file --mime-type` reports);
   - full provenance: source, URL, ref, license, the license URL, the date the license was read,
     license status, and redistributable;
   - for a generated file: its command, inputs, generator with versions, and generator license;
   - for a candidate: its gap id.

   A sample also carries:
   - its covers, in the coverage vocabulary;
   - its truth, as a list of path-and-note pairs, with `~/docs`' qualifiers carried across
     unchanged;
   - when it has no truth, a truth note giving `~/docs`' "none" reason.
4. The 97 adopted samples and the truth and doc files they link sit at their manifest paths,
   copied from `~/docs`, which stays unchanged. Sample files are ignored by git. Truth and doc
   files are committed. Each adopted sample's covers equal its covers in the coverage data.
5. The licenses of the nine adopted samples `~/docs` records as "reported", and of every
   committed truth or doc file it records as "reported", are read at their source and recorded
   as verified, with URL and date. A sample whose license doesn't allow redistribution leaves the
   corpus, and its scenarios become a gap.
6. A fetch command takes a release URL or a local directory. It downloads one uncompressed tar per
   format area and extracts the files to their manifest paths. It fails when any file's size or
   sha256 differs from the manifest, or when a manifest file is missing. A matching pack step
   builds those tars from a working copy. There are ten areas, the review's nine plus `exec`.
7. tools/coverage reads the run directory that the docproc release carrying the encoding keys
   writes.
   - Text outputs are read as UTF-8, as docproc's API defines them; `encoding` and `encoding_by`
     name the source file's encoding and are metadata only.
   - The reader reads the run directory's schema version. It reads the kept run's schema and that
     release's schema, and refuses any other, naming it. If that schema changes a manifest,
     event, or content-store shape the reader uses, the reader follows the change.
   - With the kept run, dispose still reproduces the coverage data.
8. Placement covers the curated set. docproc, built at the release carrying the encoding keys,
   runs over the curated tree, outside the repository. The library, trait, and feature placement
   reads docs-corpus's own manifest and that run, and sets each new candidate's covers. The
   vocabulary's links stay pinned to docproc `48216e1`; an ID the new run adds gets a link pinned
   to the release.
9. Each sourced candidate is fetched from its pinned URL and ref, and each generated candidate is
   made once by its recorded command from the adopted samples in the tree. Generation uses mise's
   pinned tools where they are pinned, and the versions actually run are recorded in the manifest
   and in the coverage data's candidate. The manifest's sha256 pins the generated bytes. Nothing
   regenerates them, and no candidate is edited by hand.
10. A candidate's truth is only truth it inherits unchanged from an input's truth. Otherwise it
    has none.
11. Every candidate's placed covers contain its gap's covers. For a Fair candidate, any covers its
    placement doesn't confirm become an open gap whose candidate is unavailable, recording what
    was searched and why. The file stays only if it covers a scenario no other sample does.
    email-7 stays open.
12. The check fails when:
    - a manifest entry's covers ID is outside the vocabulary;
    - a sample file is tracked by git, or a truth or doc file isn't;
    - a candidate's provenance differs from its gap's candidate;
    - two samples share a format and covers;
    - a sample's covers lie inside another sample's, whatever the format. A generated sample's
      recorded inputs are exempt, so msg_36 stays beside email-8 and old_scans-69 stays beside
      pdf-2. STANDARDS states this exception.
13. The repository's README, context, and coverage page describe the inventory, the scenario
    index, and distribution as built.

**Test seams**

- The check's verdict over the working copy, with and without `~/docs`.
- tools/coverage's commands: place-traits, dispose, and generate, each judged by its output.
- The fetch command over a local directory of packed area tars.

**Slices**

1. JSON writer: typed structures, the Python-emulating package removed, and the coverage data
   reformatted in its own commit. Sorted-key equality proves no content change; place-traits and
   dispose then reproduce it byte for byte (behavior 1).
2. License: the Apache-2.0 license, and email-5's and email-8's generator license (behavior 2).
3. The manifest for the adopted set: schema, files in place, the git-tracking rule, license
   readings, and the check's vocabulary, equality, duplicate, and containment rules
   (behaviors 3–5, 12).
4. Fetch and pack (behavior 6).
5. The run reader for the docproc release carrying the encoding keys: UTF-8 reading and the
   schema check (behavior 7). It needs that release. If the release isn't out when BUILD reaches
   this slice, BUILD escalates and hands off, with slices 1–4 committed on the branch.
6. Placement over the curated tree with docproc at that release (behavior 8).
7. Sourced candidates, including the `exec` area (behaviors 9–11).
8. Generated candidates, including the exempt inputs (behaviors 9–12).
9. Fair confirmation and the open gaps it leaves (behavior 11).

Each slice updates the docs its change touches (behavior 13), and leaves the check passing.

**Out of scope**

- Tagging, publishing release assets, making the repository public, and the gb10-2 fetch:
  snapshot's.
- docproc's encoding change, and any change to its run-directory schema or dispatch wire:
  docproc's own task and release.
- Baseline runs, and removing `~/docs`.
- Searching for new candidates beyond the review's, including for email-7.
- Byte-reproducible generation.
- Changing `~/docs`.

**Door**

Two-way. Nothing is tagged or published, and the repository stays private. The one outside
dependency is the docproc release carrying the encoding keys; this task consumes it and does not
cut it.

## Decisions

- curate: the corpus placement pins docproc v0.5.0, with cmd/docproc v0.2.3. docproc v0.6.0
  (RAR, xz, bzip2, MPEG-PS, and Ogg-video kinds; `.ogv` moves from kind ogg to the Ogg-video kind)
  and docproc-coverage's "text as the last resort" release (#! scripts route to text and get the
  polyglot scan) move placements. A later task adopts them, and the second reopens
  exec-4-open's check:polyglot.
- curate: the vocabulary's links stay pinned to docproc `48216e1`; an ID a newer run adds links to
  that run's release.
- curate: the candidates for archive-1, archive-2, archive-3, and archive-5 reuse `~/docs` paths
  (`archive/mixed-bundle.7z`, `.tar.gz`, `.tar.zst`, `archive/zip-in-zip.zip`) with different
  content, so baseline must not compare v1 runs with `~/docs` runs by path alone.
- curate: 24 samples and 26 truth and doc entries record `license_url`
  https://github.com/standards-lab/docs-corpus/blob/main/LICENSE, which resolves only once curate
  merges and LICENSE is on main; snapshot relies on it.
- review: a copyleft fixture, such as onenote-1's AGPL-3.0-or-later test.onepkg from Joplin, is
  acceptable in the public corpus when it ships unmodified with its license.
- review: `mise run place-traits` then `mise run dispose` rebuild coverage.json; a later task
  changes placements or dispositions through them, never by hand.
- plan: ~/docs is never changed. It is the reference for a corpus built from scratch in
  docs-corpus.
- plan: snapshot publishes one v1, from curate's set. docs-corpus stays private until then, and
  snapshot makes it public.
- plan: acceptance runs cite `MANIFEST.json`'s `version`.
- plan: once docs-corpus v1 is final, the baseline task reruns docproc and docinfer over it,
  repoints the acceptance citations, and removes ~/docs.
- plan: the corpus has no size cap.
